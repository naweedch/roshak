# یکپارچه‌سازی‌ها

همهٔ کلیدها فقط در متغیرهای محیطی هستند؛ پنل ← تنظیمات ← «وضعیت یکپارچه‌سازی‌ها» نشان می‌دهد کدام فعال است.

## ایمیل (SMTP)

```dotenv
EMAIL_PROVIDER=smtp
EMAIL_FROM=روشاک <no-reply@example.com>
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false        # برای پورت 465 مقدار true
SMTP_USER=...
SMTP_PASSWORD=...
```

ایمیل‌ها (تأیید حساب، بازیابی و تغییر رمز، تأیید سفارش، تغییر وضعیت و ارسال سفارش، تأیید خبرنامه، اعلان سفارش و پیام تماس و موجودی کم به فروشگاه) ابتدا در جدول `EmailOutbox`
ثبت می‌شوند و پس از پاسخ HTTP یا با کار دوره‌ای ارسال می‌شوند؛ خطای موقت SMTP با تلاش دوباره جبران می‌شود.
برای تحویل‌پذیری، SPF، DKIM و DMARC دامنهٔ فرستنده را تنظیم کنید.

## ذخیره‌سازی S3

```dotenv
STORAGE_DRIVER=s3
S3_ENDPOINT=https://s3.example.com     # برای AWS خالی بگذارید
S3_REGION=us-east-1
S3_BUCKET=roshak-media
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
S3_PUBLIC_URL=https://cdn.example.com  # نشانی عمومی همان سطل
S3_FORCE_PATH_STYLE=true               # برای MinIO و بیشتر سرویس‌های سازگار
```

`S3_PUBLIC_URL` هنگام build در CSP و `next/image` مجاز می‌شود؛ پس از تغییر آن دوباره build کنید.
تصاویر بارگذاری‌شده بر اساس محتوای فایل (نه پسوند) بررسی، به WebP تبدیل و متادیتای آن‌ها (از جمله موقعیت مکانی) حذف می‌شود؛ حداکثر ۸ مگابایت.

## درگاه پرداخت زرین‌پال

> آداپتور زرین‌پال (`src/server/payments/zarinpal.ts`، API نسخهٔ ۴) پیاده‌سازی شده اما **با درگاه واقعی یا sandbox آزموده نشده است.**
> پیش از فعال‌سازی عمومی: یک پرداخت sandbox موفق و یک ناموفق، سپس یک پرداخت واقعی کم‌مبلغ و بازپرداخت دستی آن را بررسی کنید.

1. `ZARINPAL_MERCHANT_ID` را تنظیم کنید (برای آزمایش `ZARINPAL_SANDBOX=true`).
2. پنل ← تنظیمات ← «درگاه‌های پرداخت فعال» ← زرین‌پال.
3. آدرس بازگشت به‌طور خودکار `APP_URL/api/v1/payments/callback/zarinpal?pid=...` است؛ `APP_URL` باید دقیق باشد.

مبالغ تومانی برای درگاه به ریال (×۱۰) تبدیل می‌شوند. وضعیت «پرداخت‌شده» فقط پس از فراخوانی verify سمت سرور
و تطبیق مبلغ ثبت می‌شود و بازگشت کاربر به سایت به‌تنهایی کافی نیست. اگر بازگشت کاربر نرسد، کار دوره‌ای پیش از لغو سفارش
وضعیت پرداخت را از درگاه استعلام می‌کند. بازپرداخت در پنل فقط **ثبت** می‌شود؛ انتقال پول را از پنل درگاه یا بانک انجام دهید.

### درگاه آزمایشی

با `PAYMENT_TEST_MODE=true` (فقط توسعه یا staging) فعال می‌شود و در همه‌جا برچسب «آزمایشی» دارد. تأیید آن همان مسیر درگاه واقعی را طی می‌کند
(ثبت تراکنش در جدول `TestGatewayTransaction` و verify سمت سرور) و وب‌هوک امضاشده با HMAC (`PAYMENT_TEST_WEBHOOK_SECRET`) دارد.

## Redis

`REDIS_URL=redis://...` — شمارنده‌های محدودیت نرخ (ورود، ثبت‌نام، بازیابی رمز، جست‌وجو، بارگذاری و ...) بین نمونه‌های برنامه مشترک می‌شوند.
بدون آن، هر نمونه حافظهٔ خودش را دارد (برای یک نمونه کافی است).

## اینستاگرام

`INSTAGRAM_ACCESS_TOKEN` (توکن بلندمدت Instagram Graph API از حساب Business/Creator) — آخرین پست‌ها در صفحهٔ اصلی نمایش داده می‌شوند.
بدون توکن یا در صورت خطا، بخش اینستاگرام نمایش داده نمی‌شود (هیچ پست ساختگی نمایش داده نمی‌شود). توکن هر ۶۰ روز باید تمدید شود.

## Google Analytics

فیلدهای «آمار بازدید» و «شناسهٔ Google Analytics» در تنظیمات ذخیره می‌شوند، اما **اسکریپت آمار هنوز در صفحات بارگذاری نمی‌شود** ([status.md](status.md)).
`Google Search Console` از فیلد «کد تأیید» در تنظیمات به‌صورت متاتگ کار می‌کند.
