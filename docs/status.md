# وضعیت پروژه و کارهای باقی‌مانده

آخرین به‌روزرسانی: ۲۵ مهر ۱۴۰۵ (2026-10-17). این فهرست فقط چیزی را «انجام‌شده» می‌نامد که در کد وجود دارد؛
ستون «آزموده» می‌گوید با چه چیزی بررسی شده است.

## پیاده‌سازی‌شده

| بخش | آزموده |
|---|---|
| کاتالوگ، فیلتر، جست‌وجوی فارسی، صفحهٔ محصول، نمای چرخشی از عکس واقعی | e2e (خرید)، بررسی دستی در مرورگر |
| سبد خرید سمت سرور (مهمان و کاربر)، کد تخفیف | یکپارچه + e2e |
| ثبت سفارش در یک تراکنش: کسر اتمی موجودی، idempotency، قفل و سقف تخفیف | یکپارچه (شامل رقابت هم‌زمان روی آخرین عدد و سقف کد) |
| درگاه آزمایشی با تأیید سمت سرور، وب‌هوک امضاشده، انقضای رزرو و بازگرداندن موجودی | واحد + یکپارچه + e2e (خرید کامل تا «سفارش شما ثبت شد») |
| مسیر بازگشت از درگاه (`/api/v1/payments/callback/...`) | یکپارچه (route واقعی) + e2e |
| حساب کاربری، ورود، نشست‌ها، Argon2id، تأیید ایمیل، بازیابی رمز | یکپارچه (ورود) |
| پنل مدیریت: پیشخوان، سفارش‌ها، محصولات، انبار، دسته/مجموعه، تخفیف، مشتریان، نظرات، محتوا، مجله، تنظیمات، ممیزی | e2e (دیدن سفارش پرداخت‌شده، کنترل دسترسی) + بررسی دستی |
| نقش‌ها و مجوزها در سرور، محافظت از آخرین مدیر ارشد، بررسی مبدأ درخواست | واحد + یکپارچه + e2e |
| ایمیل با صف خروجی (log / SMTP) | — (SMTP واقعی آزموده نشده) |
| ذخیره‌سازی تصویر (local / S3)، پردازش WebP و حذف متادیتا | local بررسی دستی؛ S3 آزموده نشده |
| سئو: متادیتا، JSON-LD، نقشهٔ سایت، robots | بررسی دستی خروجی |
| اسکریپت‌ها: `admin:create`، `jobs:run`، `db:local` | اجرای دستی |
| مستندات، `.env.example`، Dockerfile، docker-compose، CI | Docker و CI **اجرا نشده‌اند** (پایین) |

## نتیجهٔ آخرین اجرای بررسی‌ها (2026-10-17)

| بررسی | نتیجه |
|---|---|
| `npm run typecheck` | موفق |
| `npm run lint` | بدون خطا؛ ۲ هشدار اطلاعاتی (React Compiler فرم‌های react-hook-form را بهینه نمی‌کند) |
| `npm run test:unit` | ۵۱ از ۵۱ موفق |
| `npm run test:integration` | ۲۵ از ۲۵ موفق |
| `npm run test:e2e` (desktop) | خرید کامل، پنل و کنترل دسترسی موفق؛ بررسی دسترس‌پذیری صفحات فروشگاه به‌خاطر یک خطای سربرگ ناموفق (پایین) |
| `npm run build` | موفق، بدون هشدار (۹۶ صفحه). یک اجرای میانی با خطای گذرای بارگذاری ماژول `pg` در ویندوز شکست خورد و تکرار آن موفق بود. اجرای خروجی standalone: `/api/health`، صفحهٔ اصلی و فروشگاه پاسخ ۲۰۰ و سربرگ‌های امنیتی درست |

## کارهای باقی‌مانده و محدودیت‌های شناخته‌شده

### پیش از راه‌اندازی عمومی
- **درگاه زرین‌پال با تراکنش واقعی یا sandbox آزموده نشده است.** آداپتور طبق مستندات API نسخهٔ ۴ نوشته شده؛ یک پرداخت sandbox و یک پرداخت واقعی کم‌مبلغ لازم است.
- **Dockerfile و docker-compose ساخته و اجرا نشده‌اند** (Docker روی ماشین توسعه نصب نبود).
- **گردش‌کار CI (`.github/workflows/ci.yml`) هنوز اجرا نشده است** (پروژه هنوز روی GitHub نیست).
- ارسال واقعی SMTP و ذخیره‌سازی S3 آزموده نشده‌اند.

### خطاهای باز (فایل‌های در اختیار بازطراحی هیرو)
- axe «label-content-name-mismatch» (جدی) روی لینک لوگو در `site-header.tsx`: `aria-label="روشاک، صفحهٔ اصلی"` با متن قابل‌مشاهدهٔ «روشاک ROSHAK» نمی‌خواند.
  راه‌حل آزموده‌شده: حذف `aria-label` و افزودن `<span className="sr-only">، صفحهٔ اصلی</span>` داخل لینک.

### امکانات ناقص
- **Google Analytics**: شناسه و گزینهٔ آمار در تنظیمات ذخیره می‌شوند اما اسکریپت آمار در صفحات بارگذاری نمی‌شود (متن راهنمای پنل همین را می‌گوید).
  پیاده‌سازی باید با رضایت کاربر (cookie consent) همراه باشد.
- **پیام‌های فرم تماس و مشترکان خبرنامه** در پایگاه داده ذخیره و به ایمیل فروشگاه اطلاع داده می‌شوند، اما صفحهٔ مشاهده یا خروجی در پنل ندارند.
- **بازپرداخت** در پنل فقط ثبت حسابداری است؛ انتقال پول از پنل درگاه یا بانک انجام می‌شود.
- **نمای ۳۶۰ درجهٔ کامل** نیاز به ۸ فریم یا بیشتر (ترجیحاً ۲۴ تا ۳۶) از میز گردان دارد؛ محصولات فعلی حداکثر ۲ زاویهٔ واقعی دارند. — [photos.md](photos.md)
- رنگ مشکی محصول «گلبرگ» فقط عکس پشت دارد؛ عکس جلوی همین رنگ لازم است.
- مدل سه‌بعدی (GLB) برای هیچ لباسی وجود ندارد؛ زبانهٔ «نمای سه‌بعدی» فقط با مدل واقعی نمایش داده می‌شود.
- بازطراحی بخش آغازین صفحهٔ اصلی (هیرو) در جلسهٔ دیگری در حال انجام است.

### پوشش تست
- تست سرتاسری پروژهٔ «mobile» (Pixel 7) در آخرین اجرا گزارش جداگانه دارد؛ جریان‌های خبرنامه، فرم تماس، نظرات، علاقه‌مندی‌ها،
  ویرایش محصول و بازپرداخت در پنل تست خودکار سرتاسری ندارند (منطق سرور بازپرداخت و وضعیت سفارش هم هنوز تست یکپارچه ندارد).
- تست‌های سرتاسری روی پایگاه دادهٔ سرور در حال اجرا (معمولاً پایگاه توسعه) سفارش آزمایشی ثبت می‌کنند.
- در تست‌های یکپارچه هشدار `DeprecationWarning: client.query() ... already executing` از کتابخانهٔ pg/آداپتور Prisma چاپ می‌شود؛ روی نتیجه اثری ندارد.
