# ساخت اولین مدیر

برنامه هیچ حساب یا رمز پیش‌فرضی ندارد. اولین مدیر ارشد را از خط فرمان بسازید:

```bash
npm run admin:create -- --email owner@example.com --first-name نام --last-name خانوادگی
```

رمز به‌صورت پنهان دو بار پرسیده می‌شود (حداقل ۱۲ کاراکتر، رایج یا فقط عددی پذیرفته نمی‌شود، نباید شامل بخش نام کاربری ایمیل باشد).
برای اجرای غیرتعاملی (CI یا کانتینر) رمز را با متغیر `ADMIN_PASSWORD` بدهید و پس از اجرا از تاریخچهٔ شل پاک کنید.

| گزینه | توضیح |
|---|---|
| `--email` | الزامی |
| `--role` | `SUPER_ADMIN` (پیش‌فرض)، `ADMIN`، `PRODUCT_MANAGER`، `ORDER_MANAGER`، `CONTENT_MANAGER` |
| `--reset` | برای حساب موجود: تنظیم رمز و نقش جدید و ابطال همهٔ نشست‌های آن |

هر اجرا در گزارش ممیزی با عامل `cli` ثبت می‌شود.

## نقش‌ها

| نقش | دسترسی |
|---|---|
| مدیر ارشد | همه‌چیز، از جمله تغییر نقش کارکنان |
| مدیر | همه‌چیز به‌جز مدیریت نقش کارکنان |
| مدیر محصول | محصولات، انبار، دسته و مجموعه، بارگذاری تصویر، بررسی نظرات، مشاهدهٔ تخفیف‌ها |
| مدیر سفارش | سفارش‌ها (وضعیت، بازپرداخت، خروجی)، مشاهدهٔ مشتریان، محصولات، انبار و تخفیف‌ها |
| مدیر محتوا | بنرها، اطلاعیه‌ها، صفحات، مجله، پرسش‌ها، بررسی نظرات |

ماتریس دقیق در `src/lib/rbac.ts` است و هر API و صفحه آن را در سرور بررسی می‌کند (پنهان شدن دکمه‌ها فقط برای راحتی است).

## کارکنان بعدی

پس از ورود مدیر ارشد: پنل ← مشتریان ← پروندهٔ کاربر ← «نقش». کاربر ابتدا باید خودش در سایت ثبت‌نام کرده باشد،
یا مستقیماً با `npm run admin:create -- --email ... --role ...` ساخته شود.

قواعد حفاظتی: هیچ‌کس نقش یا وضعیت حساب خودش را تغییر نمی‌دهد؛ آخرین مدیر ارشد فعال قابل تنزل یا تعلیق نیست؛
تعلیق یا تغییر نقش، همهٔ نشست‌های آن کاربر را باطل می‌کند.

## حساب مدیر توسعه

`npm run db:seed` در محیط توسعه از `SEED_ADMIN_EMAIL` و `SEED_ADMIN_PASSWORD` یک مدیر ارشد می‌سازد.
اگر این دو خالی باشند، حسابی ساخته نمی‌شود. seed در `NODE_ENV=production` اجرا نمی‌شود.
